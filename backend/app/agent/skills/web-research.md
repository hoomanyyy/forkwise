# Deep web research

## 1. Frame the question
Restate the question, what a complete answer needs (for example prices, dates, pros and cons, a recommendation) and the time frame. Plan five to fifteen searches that cover each part separately.

## 2. Search well
- Short, specific queries. One topic per query. Use the current year for anything that changes.
- Prefer primary sources: official sites, documentation, pricing pages, filings, papers, government data. Use news and blogs for context, forums only for user experience.
- Open the pages that matter with the fetch tool instead of trusting snippets.

## 3. Cross-check
- Confirm every important number or claim in two independent sources, or say it rests on one.
- Note the date of each source. Newer beats older for prices, versions and rules.
- When sources disagree, report both and say which is more credible and why.

## 4. Write the report
- Start with the answer in two or three sentences.
- Then the details, organized by the user's question, not by source. Tables for comparisons.
- Paraphrase; short quotes only when the exact wording matters.
- End with the open questions or risks, and a Sources list with titles and links.
- For a long report, write it to a markdown or docx file in the workspace and give the user the file.
